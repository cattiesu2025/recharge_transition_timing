## Purpose and Claim

检验 ONSET 能否从驾驶/着陆中的运动响应，扩展到机器人任务阶段切换：在任务收益与电量储备之间权衡的策略，何时停止作业并开始返回充电站？

新增价值有两点：事件从局部制动扩展到一段有明确目的地的导航行为；正常原始场景中允许“不返回”，而非只有移除危险的 counterfactual 才没有事件。

这是基于 MiniGrid 的自定义电池与作业任务，不是官方现成充电 benchmark。MiniGrid 提供可扩展环境基础，但电池、充电、作业和事件确认规则均需自行实现并公开。[官方创建教程](https://minigrid.farama.org/v2.5.0/content/create_env_tutorial/)

本计划提供独立完整实验，不依赖 LunarLander 的效应方向或显著性。先做 LunarLander 是排程优先级，不是按其结果挑选更容易成功的环境。所有候选数值需在正式运行前冻结，沿用 highway 的数据保留原则，不修改其冻结协议。

## Task and State Design

采用小型、完全可观测、离散动作的任务地图。首版使用清晰的作业区和充电支路，避免把部分可观测记忆、复杂寻路和随机障碍同时引入。

- 一个作业点、一个充电站，二者通过可控长度走廊连接。作业点与充电支路不重合，进入充电支路不会同时推进其他任务。初始位置在作业区，朝向固定。
- 在作业点执行 `WORK` 获得一个工作单位并耗电；目标是在固定时限内完成 `Q` 个工作单位。只有实际完成工作才给产出奖励，重复走动不能获任务奖励。
- 原子动作采用转左、转右、前进、等待、作业、充电。`CHARGE` 仅在充电站有效，需要连续若干步逐渐恢复电量，每步计时。无效动作明确为有时间/基础耗电成本的 no-op。
- 不提供 `RETURN_TO_CHARGER` 宏动作，也不用脚本电量阈值代替被解释策略的决策。
- 移动、转向、等待、工作分别有明确耗电；到零电量且尚未达到充电可用状态时任务失败。规定最后一步到站、电池归零、充电动作的先后顺序并写测试，避免边界套利。
- 达到任务配额、能量耗尽或时限到达才结束。第一次充电不结束 episode：继续执行剩余任务，以免终止规则人为奖励过早返航。
- 策略观测包含布局、位置、方向、电池、剩余任务量、剩余时间及充电进度；使用固定归一化全状态编码。对有限时域策略必须提供剩余时间，避免隐含非 Markov 状态。

暴露 `t0` 为共同作业状态交给策略的时刻，所有条件共享相同位置、电量、任务余量和时钟。计量目标是“从标准化作业状态到返航启动”，不能暗示此前已经观察到每个策略自主作业。记录 `t0` 后实际 WORK 次数，允许立即返航。

环境参数的 pilot 起点：约 17×9 的地图边界、3 档走廊距离、每 episode 最多 300 个动作步。电池容量、各动作耗电、任务配额和充电速率须用手算路径成本校准，不为了形成目标排序而调整。网格时间单位为 **动作步**，没有机器人硬件模型时不换算成真实秒。

## Reward Conditions and Agents

定义电量储备 margin：`m(s) = b(s) - E_min_to_dock(s)`，其中 `E_min_to_dock` 按地图、方向与动作耗电计算，包含转向，不能仅用曼哈顿距离。该量用于奖励及分析，不用于硬编码返航动作。

候选分解：

`r = w_P * completed_work - w_R * reserve_deficit + r_common`，

`reserve_deficit = clip((m_safe - m(s)) / B_max, 0, 1)`。

`r_common` 包含共同的耗尽惩罚、完成配额奖励和时间成本。首次到站、充电量和返航事件本身不额外给奖励，防止围着充电站刷分；耗尽惩罚三组一致。储备阈值 `m_safe` 固定，不能因策略条件而变。奖励尺度在 pilot 校准后冻结。

| 条件 | pilot 相对权重 `(w_P, w_R)` | 意义                           |
| ---- | --------------------------- | ------------------------------ |
| RES  | `(0.25, 1.0)`               | 储备不足代价较高，检验较早返航 |
| BAL  | `(0.625, 0.625)`            | 中间权衡，检查条件分组         |
| PROD | `(1.0, 0.25)`               | 产出权重较高，检验延后返航     |

三组同一 Double DQN、网络、训练配置及 seed 内场景序列，仅权重变化。[Double DQN 论文](https://arxiv.org/abs/1509.06461) 是训练算法出处；三奖励条件是被解释策略，不是三种解释算法。

固定储备阈值返航控制器仅用于环境可行性与轨迹标签校准；它是本实验自定义参考规则，无外部论文归属，不能拿其必然按阈值返航的表现作为 ONSET 能解释 RL 的主证据。

## ONSET Definition

主要事件：**第一次从作业区进入充电专用支路并持续向充电站推进的返航**。该定义依赖地图语义，不能外推为通用意图识别。

1. 候选 onset 是离开作业区、进入充电专用支路的首个实际移动；对应状态位置必须改变，朝向命令或撞墙 no-op 不算。
2. 候选之后至多 `W = 8` 个动作步内，至少完成 `k = 3` 次沿路径朝充电站的实际移动，允许必要转向。
3. 确认前不得返回作业区、执行 WORK、发生耗尽或 episode 终止；连续推进对应的距离必须降低。所有网格的支路长度至少容纳该确认段。
4. 最早通过确认的候选离区动作记为 onset；第 3 次推进记为 confirmation。先前未确认的离区、反向走动和再作业另存为候选，不隐式抹掉。

**不以最终到达或成功充电作为 onset 成立条件。** 这样已启动且确认的返航即使随后耗尽，仍保留 onset；到站率、首次充电时间和返航途中失败另外报告。代价是该事件表示“已确认的返航行为段”，不证明内部意图或最终成功。

主定义与辅助定义同时记录：第一次朝站移动、离开作业区、第一次到站/充电。后两者帮助分辨决策延迟和路径耗时，但不能拿到站时间直接替代返航 onset。窗口 `W` 与推进次数 `k` 通过预先标注轨迹校准；敏感性候选为 `k=2/4`，不得选择最能拉开奖励条件的定义。

## Exposure Grid and Controls

候选开发网格和独立 held-out 网格各 27 场景：返航路径距离 3 档 × 初始电量 3 档 × 剩余工作配额 3 档。地图尺寸、动作成本保持一致。两套网格的变化轴数值分离、都在训练分布支持内；训练中含足量与不足量电池场景，不把充足电量作为未见过的观测干预。

将主网格设计为可先工作、可返航、但完成全部配额需要至少一次充电的区域；由动作能耗和任务成本推导可行区间。另建匹配的充足电量对照，使无充电完成任务后仍至少剩余 `m_safe`。这避免用“原本就完全不需要充电”的场景稀释主时间估计，同时在正常可解任务中显式评估事件不发生。

如果 27 场景的全因子组合不能同时满足上述几何/电量条件，采用预先列出的可行场景 manifest，不能默默裁剪。场景数量、估计门槛和预算在冻结时一并更新。

| 实验         | 操作                                                 | 要回答的问题                                                   |
| ------------ | ---------------------------------------------------- | -------------------------------------------------------------- |
| 主要返航比较 | 三奖励条件，20 正式 seed，匹配的需充电网格           | RES–PROD 的返航延迟差及发生率                                  |
| 充足电量干预 | 固定模型、地图和任务，提高起始电量至可不充电完成任务 | 返回是否延后/消失，是否仍能完成工作                            |
| 语义对照     | 同一批轨迹上的简单检测器与 ONSET                     | 单步趋近是否混淆绕行、试探和返航                               |
| 阈值敏感性   | 同一轨迹，固定辅助确认长度                           | 主要结论是否依赖单一确认段长度                                 |
| 路径距离分层 | 利用主网格三个距离层                                 | 原始电量与真正的可返航储备是否一致；仅辅助解释，不预设时间排序 |

不把移除充电站作为“无触发”对照：这会删除行动机会并改变可行性。首版也不加入动态障碍、多充电站、多机器人或视觉感知学习。

## Training and Analysis

执行顺序：手算/脚本可行性检查 → 环境与合成轨迹验证 → 3 pilot seed × 3 条件 → 冻结配置和 manifest → 20 正式 seed × 3 条件 → 一次完整 held-out/干预评估。

pilot 起点每策略 300,000 步，正式预算在 pilot 后统一冻结。采用固定训练步数的最后 checkpoint，保留所有 seed；不用主要时间差或预期排序挑模型。训练基础设施错误可原配置重试，低产出或耗尽多的策略不能替换成好 seed。

主要估计：每 seed 对双方都出现确认返航的匹配暴露计算 `median(tau_PROD - tau_RES)`，再对 20 个 seed 取中位数和 10,000 次 seed bootstrap 95% CI。CI 完全大于 0 支持 R1；exact sign test 辅助。候选估计门槛为每 seed 至少 18/27 个共同事件且 20 seed 均可估计，正式运行前冻结。

达不到门槛，报告事件/终局与不可估计原因，不把没返航的 PROD 策略当作无限晚以制造时间优势。达到门槛仍只解释共同事件子集，不假设缺失随机。BAL 对比、距离层和起始电量层为辅助，不代替主要对比。

每个 episode 保留相互独立的事件与终局字段：

- 返航是否确认、候选次数、onset/confirmation、首次到站/充电时间；
- 到时限仍无返航、配额完成而无返航、返航确认前耗尽、确认后耗尽、技术错误；
- 总完成工作数、任务成功、耗尽、充电次数、行走/等待/作业步数；
- onset 时电量、最小到站能耗、储备 margin、剩余配额。

工作完成而不返航是 competing terminal outcome，不是无限长 latency；耗尽也不是无信息删失。仅到观察时限仍未发生且未终止的情形标记行政右删失。不将这些类别合并后套普通生存曲线。充足电量组先报告全部分母的事件率与任务成功率，再报告有足够共同事件时的条件延迟。

如果 RES 较早返回但几乎不工作，或 PROD 只是大量耗尽，则不得把时间差描述为两个胜任策略的细腻偏好差异。任务质量始终与 onset 一起展示。充电成本、路径距离变化后，原始电池读数不一定单调，优先使用 margin 解释。

目标一张地图加电量/工作状态时间轴，一张 RES/BAL/PROD 的事件率、条件 onset 差、任务成功/耗尽及 onset margin 表。代表性轨迹使用预先规定的中位效应选择规则；不返航例子按 manifest 顺序选取满足类别的首例，并标明它只是示例。

**pilot 可行性条件：** 任务存在真实作业/返航权衡；学习策略能够完成工作和补能；确认规则能排除简单试探；充足电量下允许不返航完成任务。条件不满足时修正并记录，不能看正式效应后倒改定义。

## Resource Estimate

仅供排程：pilot 9 策略 × 0.3M 步 = 2.7M 步；如果正式冻结为同预算，60 策略共 18M 步。27 原始暴露及其 27 个充足电量配对共 `60 × 27 × 2 = 3,240` episodes，开发评估另计。按首个 pilot 实测吞吐、内存和收敛再填写 Katana 墙钟时间，不承诺未经测试的 GPU 小时。

工程粗估 4–7 个工作日，不含集群排队、长训练和返工。主要成本是自定义任务的有效性与防漏洞检查，而不只是训练。时间不足就保留本计划，不以 3-seed pilot 的排序充当论文确认性结果。
